NFL Contract Value Pipeline & Ask Tool

Technologies: Python, Dagster+ Serverless, Snowflake, dbt, Postgres, FastAPI, HTMX, Claude API, GitHub Actions, Railway

  • 1 Built a production ELT pipeline: Dagster orchestrates nflverse play-by-play, schedules, and OverTheCap contract data (2015 to present) into Snowflake RAW, STAGING, and MARTS layers via dbt; 20 assets with season partitions, refreshed on schedule by Dagster+ Serverless with no dependency on a local machine.
  • 2 Stopped bad data before publish: each load deletes, copies, and audits inside one Snowflake transaction and rolls back on failure. Wrote a public postmortem on a race between blocking checks and downstream automation, and fixed it by validating before commit.
  • 3 Shipped a serving layer: an audited Dagster asset publishes finished marts to Postgres in a single-transaction swap, verified against Snowflake by row counts and primary-key fingerprints, so the website never queries the warehouse.
  • 4 Modeled spend vs. performance: QB cap share against EPA per dropback, with "worth it" defined as EPA above a fitted value line; documented edge cases (mid-season trades, missing cap rows) as tested decisions, 43/43 dbt tests passing in prod.
  • 5 Grounded LLM question answering: a Claude Haiku tool loop over select-only, parameterized, read-only queries with timeouts and row caps; code rejects any number not returned by a query, and out-of-scope questions get a "no data" reply. 81-question eval suite scores 78/81 (30/30 refusals) at ~$0.0005 and 4s per question; chose the model over GLM-5.3 Flash on eval accuracy, cost, and latency.
  • 6 Ran it like production: live public deploy with rate limits, spend caps, and no stored user data; required CI checks (pytest with mutation-checked tests, dbt parse, gitleaks full-history secret scan); Snowflake key-pair auth, least-privilege role, and a 10-credit monthly resource monitor.
